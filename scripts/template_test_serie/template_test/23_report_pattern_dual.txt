[F] CONDITIONAL — drei Zustände: explicit / fallback / nothing
================================================================================
Die report_pattern_id im gtree nutzt eine Sentinel-Konvention:
  • Feld fehlt   → gar nichts (weder Tabelle noch Projekt-Default)
  • Wert = -1    → Projekt-Default-Fallback ist aktiv
  • Wert > 0     → Tabelle hat ein eigenes Pattern explizit zugewiesen

Raw-Werte aus dem gtree:
  report_pattern_id   = {:report_pattern_id:}
  report_pattern_name = {:report_pattern_name:}
  form_set_id         = {:form_set_id:}
  form_set_name       = {:form_set_name:}

{:if report_pattern_id gt 0:}
  ✓ TABLE-SPECIFIC: Tabelle hat ein eigenes ReportPattern "{:report_pattern_name:}" (id={:report_pattern_id:}).
    Hier kannst du table-spezifische Anpassungen vom User erwarten (Farben, Fonts, Captions etc.).
{:elseif report_pattern_id eq -1:}
  ↳ PROJECT-DEFAULT FALLBACK: kein eigenes Pattern, aber Projekt-Default "{:report_pattern_name:}" greift.
    Daten kommen aus dem generischen Project-Default — kein User-Customising.
{:else:}
  ✗ NOTHING: Tabelle hat KEIN ReportPattern und auch kein Projekt-Default.
    Tipp: Im TableModal Tab "Reports" oder in Projekt-Settings einen ReportPattern wählen.
{:endif:}
